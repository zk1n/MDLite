## Direct dependencies and platform roles

`crop = 0.4.3` は本文・COW履歴・byte/UTF-16 metricと書記素境界に使用し、MSRVは1.85、宣言ライセンスはMIT。
`utf16-metric`／`graphemes`と通常のdefault SIMDを使用し、極端な試験用chunk設定は使用しない。
`pulldown-cmark = 0.13.4` はparserのみを使用し、未使用のdefault HTML/CLI featuresを無効にした。
`linkify = 0.11.0` はGFM裸リンク候補の範囲抽出、`smallvec`は通常1件の原文spanをinlineで保持する。
Windows CP932はWindows APIを使用し、`encoding_rs`は非WindowsのSHIFT_JIS fallbackを維持する。
`unicode-segmentation`は派生表示・未確定文字列の境界に残し、cropの原文と同期する第二の編集engineには使わない。

RustSecの公式database snapshot `d8325cf4f578e2df4cc5b98a30e9f46b3b88e9f0`（2026-10-13）の1289件をlockのpackage名で照合し、
一致したsecurity/unsound advisoryの版範囲を個別に確認した。該当したsecurity/unsound記録は現在のlock版でpatchedまたはunaffected。
これはpackage照合と記載範囲の確認であり、`cargo audit`／`cargo deny`全体のPASSや未知の問題がないことを意味しない。

## Image input and memory budgets

`src/assets.rs` bounds raster input files at 512 MiB and SVG/XML input at 8 MiB. Raster files are read through a capped file reader; the decoder does not first copy the complete encoded file into a `Vec`. SVG input is held in memory for XML parsing, and `roxmltree` is configured with DTD disabled and a 16,384-node limit. SVG nesting is limited to 256 levels and `<use>` elements to 128. Script, `foreignObject`, embedded image elements, event attributes, external links and CSS URLs, external font rules, and external font elements remain rejected. Only system fonts are loaded for SVG text, from one process-wide database.

Every format is checked against 16,384 pixels per side and checked `width × height × 4` arithmetic before allocating the RGBA/BGRA output or animation canvas. One expanded output frame or matching Direct2D bitmap may use up to 256 MiB. `assets::image_dimensions` applies those checks without rasterizing; `assets::decoded_bytes` returns the checked byte estimate for one output frame or bitmap. Image import validates before creating a destination and streams the encoded file copy through the same input cap; failed partial copies are removed.

These are per-image bounds, not a total-process memory guarantee. `image::Limits.max_alloc` in image 0.25.10 is a non-strict limit on the decoder's simultaneous allocations, including its output buffer; some decoders may ignore it. The 0.25.10 WebP decoder inherits the trait's dimension-only `set_limits` behavior and does not enforce `max_alloc`, so its canvas/output dimensions are checked directly before frame decoding. Decoder-internal scratch space, RGBA conversion buffers, allocator overhead, loaded system fonts, and Direct2D/native cache retention are outside a strict aggregate limit. The native cache applies its own estimated retained-resource budget; animated GIF accounting includes its current frame and disposal canvas, while WebP codec internals remain unmeasured.

API references: [`image::Limits` 0.25.10](https://docs.rs/image/0.25.10/image/struct.Limits.html), [`image::ImageDecoder::set_limits` 0.25.10](https://docs.rs/image/0.25.10/image/trait.ImageDecoder.html#method.set_limits), [WebP decoder source 0.25.10](https://docs.rs/image/0.25.10/src/image/codecs/webp/decoder.rs.html), [`roxmltree::ParsingOptions` 0.20.0](https://docs.rs/roxmltree/0.20.0/roxmltree/struct.ParsingOptions.html), and [`usvg::Tree::from_xmltree` 0.45.1](https://docs.rs/usvg/0.45.1/usvg/struct.Tree.html#method.from_xmltree).
